# 容错中性原子量子处理器编译器开发方案

版本：v1.0  
日期：2026-09-03  
状态：开发设计；不代表下述新增模块已经实现

## 1. 文档依据与项目目标

本方案依据 `compiler framework.txt`、现有编译器实现及本次讨论中已确认的补充规则编写。补充规则优先于原始文本中被修订的内容。本次交付仅为开发方案，不修改现有编译算法。

项目目标是构建面向 surface-code 编码的容错中性原子处理器编译器，将输入量子线路逐层转换为逻辑操作 DAG、逻辑比特空间映射、码块路由与指令调度方案。

当前开发重点为：

1. 构建具有明确几何坐标与资源容量的 processor 模型。
2. 设计逻辑比特到 storage zone 的初始 mapping 算法。
3. 设计基于 CZ block 的 routing 与 instruction scheduling 算法。
4. 接入已有魔法态转换及 patch rotation 编译算法。
5. 输出可验证、可序列化、可视化的调度结果。

本阶段仅以 **AOD stage 总数**作为优化目标，不将移动距离、门执行时间或总运行时间隐式加入目标函数。接口需支持后续替换代价函数。

## 2. 已确认的执行语义与范围

### 2.1 术语

- **Logical qubit**：编码后的逻辑比特，使用稳定标识，不随位置变化。
- **Patch**：容纳码块的空间位置；patch ID 与几何坐标绑定。
- **Data block / ancilla block**：一个逻辑比特的数据原子集合和辅助原子集合，分别存放于两个 patch，保留各自在原始码块中的相对位置。
- **Patch pair**：entanglement zone 内两个相互配对、具有小水平偏移的 patch。
- **CZ family**：`cz` 与 `icz` 的统称。
- **Deformation**：当前指 `rot`、`folding`、`unfolding`。
- **Instruction block（IB）**：输出调度序列的组织单元；IB 本身不意味着其中所有指令可以同时执行。

### 2.2 操作分类

| 操作类别 | 当前操作 | 区域要求 | 调度处理 |
| --- | --- | --- | --- |
| 普通操作 | H、S、Pauli 门及当前支持的其他非 CZ-family、非 deformation 指令 | 当前阶段不额外限制 zone | 优先反复释放就绪前沿 |
| Deformation | rot、folding、unfolding | 当前阶段不额外限制 zone | 单独形成 IB，之后重新调度普通操作 |
| 双逻辑比特 CZ | cz(q1, q2) | entanglement zone | 两个逻辑比特使用同一个 patch pair |
| 码块内部 CZ | icz(q) | entanglement zone | 一个逻辑比特独占一个完整 patch pair |
| 码块整体移动 | AOD stage | 由合法起止 patch 决定 | 一个 stage 形成一个 IB |

S 门保持已确认的展开规则：

```text
S(q) → folding(q) → icz(q) → S(q) → unfolding(q)
```

`icz` 在逻辑 DAG 中只有一个操作数，不能按普通双逻辑比特 CZ 检查其操作数数量，也不能将其当作普通单比特门优先执行。它不需要两个不同逻辑 patch 之间的 orientation 异或条件，但必须具有独占 patch-pair 资源。

`icz` 不加入已有 patch rotation 优化器的双比特 CZ 问题；它在后续空间路由阶段加入 CZ block sequence。

### 2.3 当前不开展的工作

- Syndrome extraction（SE）。
- 辅助码块的动态搬运。
- rotation、folding、unfolding 的码块内部原子移动展开。
- 多个码块 deformation 的空间约束建模与二次并行调度优化。
- 魔法态工厂、资源态制备及真实测量分支的完整硬件运行流程。
- 基于真实门耗时、移动耗时的时间轴优化。

上述能力保留接口，不以占位实现宣称已支持。

## 4. Processor 环境模型

### 4.1 几何配置

全局坐标单位为 μm，x 从左向右增加，y 从下向上增加。三个 zone 从下至上依次为 storage、entanglement、measurement。

配置包含：

- processor 容纳尺寸 `L, H`。
- 正整数码距 `d` 与阵列规模 `a1, b1, a2, b2`。
- storage-entanglement zone 间距 `gap_se`。
- entanglement-measurement zone 间距 `gap_em`。
- storage/measurement site 间距。
- entanglement site-pair 的水平、垂直间距与 pair 内水平偏移。

初版测试配置使用基础间距 `s > 0`：

```text
storage/measurement site pitch:  dx = dy = s
entanglement site-pair pitch:    px = py = 2s
entanglement intra-pair offset:  delta = s / 5
storage-entanglement zone gap:   gap_se = 2s
entanglement-measurement gap:    gap_em = 2s
```

这里 site-pair pitch 表示相邻 pair 对应位置之间的平移距离，不是两个 pair 边缘 site 之间的净空。

`gap_se` 和 `gap_em` 分别按相邻两个 zone 最靠近的 site 行之间的垂直距离定义，而不是两个 zone 几何中心之间的距离。

`L` 是容纳宽度。三个 zone 的阵列左对齐，最左侧 site 的横坐标均为 `x=0`；阵列实际宽度小于 `L` 时仅在右侧留白，不再要求各阵列的最右列同时位于 `x=L`。storage 最下方 site 行位于 `y=0`，measurement 最上方 site 行位于 `y=H`。

### 4.2 行列与位置标识

使用显式的 `row/col` 字段，避免原文矩阵乘积记号产生行列混淆：

| Zone | Patch 行数 | Patch 列数 | 额外结构 |
| --- | --- | --- | --- |
| storage | a1 | b1 | 上方数据区、下方辅助区 |
| measurement | a1 | b1 | 当前阶段保留环境模型 |
| entanglement | b2 | 2a2 | 每行 a2 个 patch pair |

行列编号从 0 开始。Patch 坐标为其左下角 site 坐标。Entanglement patch 使用 `(pair_row, pair_col, member)` 表示，其中 `member` 为 0 或 1。

环境对象至少提供：

```text
site_position(site_id)
patch_anchor(patch_id)
patch_sites(patch_id)
pair_members(pair_id)
pair_of(patch_id)
zone_of(patch_id)
```

### 4.3 坐标生成与校验

Storage/measurement 的 site 行列数分别为 `a1*d` 与 `b1*d`，阵列实际宽高为：

```text
W_sm = (b1*d - 1) * s
H_sm = (a1*d - 1) * s
```

Entanglement 每行有 `a2*d` 个 site pair，共 `b2*d` 行，其实际宽高为：

```text
W_ent = (a2*d - 1) * 2s + delta
H_ent = (b2*d - 1) * 2s
```

三个区域的水平原点均为 `x=0`。纵向坐标由阵列高度和两个 zone 间距确定：

```text
storage:      y_min = 0
              y_max = H_sm
entanglement: y_min = H_sm + gap_se
              y_max = H_sm + gap_se + H_ent
measurement:  y_min = H_sm + gap_se + H_ent + gap_em
              y_max = 2*H_sm + gap_se + H_ent + gap_em = H
```

因此 `H` 必须与上述计算结果一致。配置不一致时明确报错，不通过平移、拉伸阵列或修改 zone 间距进行修正。

配置校验包括：正整数规模、正 site 间距、非负 zone 间距、各阵列宽度不超过 L、计算高度与 H 一致、zone 顺序合法、不同 zone 阵列不重叠、patch/site 索引合法。

### 4.4 Storage 容量

Storage 上方 `a1//2` 行分配给数据码块，其余下方行分配给辅助码块：

```text
data rows:    a1 - a1//2, ..., a1 - 1
ancilla rows: 0, ..., a1 - a1//2 - 1
data capacity = (a1//2) * b1
```

初版为每个输入逻辑 qubit（包括魔法态资源逻辑 qubit）分配一个数据 patch 与一个辅助 patch。容量不足时在 mapping 前报错，不静默丢弃资源比特或复用仍存活的逻辑比特位置。

## 6. 数据接口设计

### 6.1 输入与状态

`LogicalOperation` 保留节点 ID、kind、逻辑 qubit 操作数、原始节点追溯信息。补充字段通过兼容性适配器接入，包括 reset epoch、资源类型以及前端确实提供的经典信息；不能凭空补造缺失信息。

`InitialMapping` 保存每个逻辑比特的 `initial_data_patch` 与 `ancilla_patch`。前者仅记录数据码块的初始位置；后者在当前阶段固定不变。数据码块的实时位置由 `PlacementState.current_data_patch` 保存。

`PlacementState` 保存：

- 各数据码块当前位置。
- 静态辅助码块位置。
- patch 占用与 patch-pair 预留状态。
- 逻辑 patch orientation、reset epoch。
- 指令已完成集合及状态版本号。

`icz` 的资源预留必须显式标记整个 pair 的唯一 owner；另一 member 不能被其他逻辑比特使用。内部原子分布留给未来 lowering 接口，不在当前模型中伪造第二个逻辑操作数。

### 6.2 输出 IR

| 类型 | 必须表达的信息 |
| --- | --- |
| `CZBlock` | block ID、cz/icz 节点 ID、内部依赖 |
| `InstructionBlock` | 类型、操作 ID、内部执行顺序或依赖、所需资源 |
| `Move` | 逻辑比特 ID、起始 patch、目标 patch |
| `AODStage` | stage ID、并行 Move 列表、前后状态 |
| `RoutingSchedule` | 有序 IB 列表、初始映射、最终状态、统计及策略配置 |

普通门 IB 可以包含经反复释放前沿获得的有依赖指令，必须保存内部顺序。CZ-family IB 中若包含依赖链，应划分为就绪批次，不能仅因属于同一 CZ block 就宣称可并行。

所有 JSON 输出包含 `schema_version`、几何配置、算法配置、随机种子（若使用）、稳定的节点与资源 ID。加载后可独立重放，不依赖进程内对象地址。

### 6.3 策略接口

```text
Mapper.map(dag, processor, cost_model) -> InitialMapping
CZBlockBuilder.build(dag) -> CZBlockSequence
PlacementPlanner.propose(block, dag_state, placement, processor) -> candidates
AODStagePlanner.plan(placement, target, processor) -> stages
CostModel.evaluate(schedule, processor) -> comparable_cost
ScheduleValidator.validate(dag, processor, mapping, schedule) -> report
```

当前 `AODStageCountCost` 返回整条调度序列中的 AOD stage 数。初始装载不作为已经发生的移动阶段计数；只统计输出 L 中的实际 AOD stage。

不同代价函数可能依赖未来增加的耗时或物理参数；参数缺失时应拒绝该代价模型，不回退为未声明的默认值。

### 6.4 Deformation 扩展接口

预留：

```text
DeformationLowerer.lower(operation, patch_state, processor) -> internal_plan
DeformationConstraintProvider.constraints(operation, placement) -> constraints
DeformationRescheduler.optimize(schedule, constraints, cost_model) -> schedule
```

初版保留 deformation 节点、资源及前后逻辑状态，不调用内部移动算法。前沿中的多个 deformation 可以被组织到同一 IB，但其空间并行合法性尚未验证，不能据此统计已实现的并行收益。

## 7. CZ block 构造方案

### 7.1 连续性与优先级

连续性使用已确认定义：若存在一个合法拓扑排序，使一组 CZ-family 门连续排列，则它们可以构成一个 CZ block。

采用已确认的调度优先级消除划分选择：

1. 反复释放普通操作前沿，直到没有普通操作可执行。
2. 释放当前 deformation 前沿；若非空，返回第 1 步。
3. 两类操作都不能继续时，才释放 CZ-family 前沿。
4. CZ-family 尽可能归入靠前的 block，不因资源容量不足而在逻辑划分阶段推迟到后续 block。

### 7.2 确定性构造

在输入 DAG 的副本上进行虚拟调度，不考虑当前 patch 位置：

1. 按上述优先级依次记录被释放的操作。
2. 同一前沿内以稳定节点 ID 排序，使结果可复现。
3. 每次释放 CZ-family 前沿后重新检查普通操作与 deformation。
4. 在生成的合法拓扑序中，将相邻的 CZ-family 操作合并为连续 block。
5. 保存拓扑序作为划分的合法性证明，输出 BS。

不能先删除所有非 CZ-family 节点，再将投影中相邻 CZ 无条件合并。被删除的 H、deformation 等仍可能是阻止两个 CZ 连续排列的依赖。

确认样例：

- `A → H → B`，另有独立 `C`：第一块包含 A、C，第二块包含 B。
- `H → A`，另有独立 `C`：先释放 H，A、C 均进入第一块。
- `folding → icz → S → unfolding`：icz 加入 BS，且不能越过 folding 或后续 S。

进入一个 CZ block 的路由阶段时，其外部前置指令已经完成。block 内 CZ/icz 按可对易操作处理，允许任意重排；DAG 中仅用于记录它们原始排列顺序的边不作为 block 内调度限制。block 与普通指令、deformation 之间的依赖仍须保留。

## 8. 初始 Mapping 算法

初版使用下面的确定性分配算法。它提供可复现的初始位置，不保证后续 AOD stage 数最少。数据码块移动后释放原 patch，返回时可选择任意空闲 data patch；辅助码块固定不动。

```text
function initial_mapping(Q, BS, processor):
    D = storage 数据 patch，按 (row, col) 升序排列
    A = storage 辅助 patch，按 (row, col) 升序排列
    if len(Q) > len(D) or len(Q) > len(A):
        报错：storage 容量不足

    first[q] = +∞，对所有 q ∈ Q
    for b = 0 .. len(BS)-1:
        for gate in BS[b]:
            for q in gate.qubits:
                first[q] = min(first[q], b)

    ordered_Q = Q 按 (first[q], q.id) 升序排列
    for i = 0 .. len(Q)-1:
        q = ordered_Q[i]
        initial_data_patch[q] = D[i]
        ancilla_patch[q] = A[i]

    return initial_data_patch, ancilla_patch
```

行号从下向上递增，因此 D 从数据区的最下行开始排序。没有 CZ/icz 的逻辑比特排在最后。初始 Mapping 不产生移动指令。

## 9. Routing 与 Instruction Scheduling

### 9.1 实现范围与状态

本阶段使用三个核心函数：`initial_mapping`、`route_and_schedule`、`plan_aod_stages`。贪心分组和位置分配写成两个小辅助函数 partition_block、assign_positions。使用字典、列表及已有 DAG 表达状态，不为每个步骤建立 Planner、Provider 或策略类。第 5、6 节列出的职责与接口作为概念说明，不要求逐项创建模块或类。

调度函数保存四项主要状态：

- G：尚未调度的指令 DAG。
- BS：按第 7 节构造的 CZ/icz block 序列。
- pos[q]：数据码块的当前位置；初始值取自 Mapping。
- L：输出 IB 序列。

辅助码块的位置使用初始 Mapping。patch 占用表由 pos 和辅助位置得到；icz 执行时还需标记整个 pair 被独占。

普通指令和 deformation 的“就绪”表示其前驱均已完成。进入 CZ-family 路由阶段时，BS[0] 中的所有指令均可参与位置分配，无需再按 G 的前沿筛选；实际执行仍要求位置、资源和 orientation 合法。“调度指令”表示将指令加入 IB、更新逻辑状态并从 G 删除，此时不驱动真实硬件。普通 IB 内按记录顺序执行；同属一个 IB 不代表全部指令并行。

重排 block 内指令时，须保留后续非 CZ-family 指令对尚未完成操作的依赖。例如原链为 A → B → H，A、B 同属一个 block；即使先调度 B，H 仍须等待 A。实现可在删除节点前保存原 DAG 的祖先关系，检查普通指令和 deformation 是否还有未完成的原始前驱或祖先，避免删除 B 后错误地提前调度 H。

### 9.2 调度主循环

```text
function route_and_schedule(dag, BS, processor, mapping, cost_fn, seed):
    G = copy(dag)
    BS = copy(BS)
    pos = copy(mapping.initial_data_patch)
    L = []
    rng = 使用 seed 初始化的随机数生成器
    groups = []

    while G 非空:
        IB = []
        while 存在就绪的普通指令:
            F = 当前就绪的普通指令，按节点 ID 排序
            按顺序调度 F，加入 IB，并从 G 删除
        if IB 非空:
            L.append(普通 IB)

        F = 当前就绪的 deformation 指令，按节点 ID 排序
        if F 非空:
            将 F 记录为 deformation IB，加入 L，并从 G 删除
            更新对应的逻辑状态
            continue

        if G 为空:
            break

        从 BS 删除已调度节点及空 block
        if groups 为空:
            groups = partition_block(BS[0], processor.pair_count)
        F = groups[0]
        target = assign_positions(F, pos, processor, rng)
        stages = plan_aod_stages(pos, target)
        for stage in stages:
            L.append(AOD IB(stage))
            同时更新 stage 中各码块的位置和占用表

        将 F 作为一个 CZ-family IB 加入 L
        从 G 和 BS[0] 删除 F 中的指令
        删除 groups[0]

    return L, pos
```

普通指令不含 cz、icz、rot、folding、unfolding。deformation 为 rot、folding、unfolding。调度器保持普通指令优先、其次 deformation、最后 CZ/icz 的顺序。G 为空即结束，不添加统一返回 storage 的尾部搬运。

### 9.3 PowerMove 贪心分组

本节采用 PowerMove §4.1 的贪心着色。论文中的 CZ stage 在此称为“门组”，与一次并行搬运的 AOD stage 区分。

以指令为顶点，两条指令共享逻辑比特时连边，得到冲突图。icz 只有一个逻辑比特，但与使用该比特的其他指令冲突。重复 CZ 必须保留为不同顶点。

```text
function partition_block(block, pair_count):
    if pair_count == 0 and block 非空:
        报错：没有可用 patch pair
    conflict[g] = block 中与 g 共享逻辑比特的其他指令
    order = 按 (-len(conflict[g]), g.id) 排序
    groups = []

    for g in order:
        找到第一个满足以下条件的组 F:
            F 中没有与 g 冲突的指令
            len(F) < pair_count
        若找到，将 g 加入 F
        否则新建组 [g]，加入 groups

    return groups
```

每条 cz/icz 占用一个 patch pair，因此组容量不能超过 pair 数，这是针对本 processor 的补充约束。一个 block 只分组一次，依次使用生成的门组；本版不引入论文 §4.2 的额外门组重排序。位置分配输入为完整门组 F，不再从 BS[0] 枚举子集。

### 9.4 PowerMove 位置分配

采用论文 §5.2 的 static/mobile/undecided 方法，将论文中的物理 qubit 替换为数据码块，计算区 interaction site 替换为 entanglement patch pair。

- static：保留当前位置。
- mobile：需要移动，目标由固定的交互伙伴或下一步分配确定。
- undecided：需要先选择一个目标 pair。

使用 target 记录目标 patch，reserved 记录已经为本轮指令分配的 pair。reserved 与当前物理占用分开：某个 pair 的原占用者可能即将离开，但目标安排不能让两个不同指令使用同一 pair。

“最近”使用 patch 左下角坐标的二维欧氏距离；同距离按 patch ID 决胜。选择 pair 时比较其中可用 member 到参考码块的距离，确定 member 后，另一个 CZ 伙伴使用另一个 member。辅助 patch 不参与选择。

```text
function assign_positions(F, pos, processor, rng):
    target = 空字典
    reserved = 空集合
    active = F 中所有逻辑比特

    # 1. 不参与本轮门的码块
    对不在 active 中、且已在 storage 的 q:
        target[q] = pos[q]
    按 (-y坐标, q.id) 遍历不在 active 中、且在 entanglement 的 q:
        target[q] = 距离 pos[q] 最近的空闲 storage data patch
        为 q 预留该目标 patch

    # 2. 为本轮交互确定保留位置的码块
    按指令 ID 遍历 F:
        if 指令是 icz(q):
            if q 在 entanglement 且其 pair 尚未 reserved:
                标记 q 为 static，target[q] = pos[q]
                为该 icz 预留整个 pair
            else:
                标记 q 为 undecided
            continue

        指令为 cz(a,b)
        if a,b 已在同一个 entanglement pair 且该 pair 未 reserved:
            保留两者位置，为该门预留 pair
            continue

        if 只有一个码块在 entanglement:
            anchor = 该码块，partner = 另一个码块
        else if 两者均在 entanglement:
            用固定种子的 rng 选择 anchor，另一个作为 partner
        else:
            按逻辑比特 ID 确定 anchor、partner

        标记 partner 为 mobile
        if anchor 在 entanglement 且其 pair 未 reserved:
            标记 anchor 为 static
            target[anchor] = pos[anchor]
            target[partner] = 同一 pair 的另一个 member
            为该门预留 pair
        else:
            标记 anchor 为 undecided，并记录 partner

    # 3. 为待定码块选位置
    按指令 ID 遍历 undecided:
        找到距 anchor 当前位置最近、且尚未 reserved 的 pair/member
        将 anchor 分配到该 member
        若为 cz，将 partner 分配到另一个 member
        若为 icz，仅分配 q，并标记整个 pair 为独占
        为该门预留 pair

    检查目标容量、目标互斥、配对、icz 独占及 orientation
    return target
```

返回 storage 使用已确认的二维最近空闲 data patch，替代论文的竖直向下搜索。此处 storage 空闲 patch 指当前未占用且未被本轮预留的 patch；已参与本轮、尚未搬走的数据码块所在位置不能提前当作空位。

已在同一 pair 的 CZ 保留原位置；icz 可保留其当前 member，并要求同 pair 的其他码块离开。为目标 pair 预留位置不代表移动已经完成，实际占用由 AOD 调度检查。找不到合法位置时报告具体资源不足，不恢复全排列枚举。

这是 PowerMove 在逻辑 patch 上的适配：论文没有 icz、独占 pair 或码块内部变形。icz 只记录码块所在 member，内部移动仍留待下一层。

### 9.5 PowerMove AOD 分组与顺序

采用论文 §5.3 的距离升序 first-fit 分组，以及 §6.1 的返回 storage 优先排序，并加入移动之间的占用依赖。一个 Coll-Move 对应本项目的一个 AOD stage，当前仍输出顺序 stage，不增加多 AOD 硬件参数。

如果 Move A 的目标 patch 是 Move B 的起始 patch，建立依赖 B → A。规划器先为 B 分配 stage，再为 A 分配 stage，并要求 `stage(A) >= stage(B)`。若两条移动满足非交叉约束，可以放在同一个 stage 中；这不要求 B 在硬件上单独执行完后才开始 A。

```text
function plan_aod_stages(pos, target):
    moves = [(q, pos[q], target[q]) for q if pos[q] != target[q]]
    建立移动依赖图 D：若 A.target == B.start，加入边 B → A
    若目标被不移动的码块占用，报告目标占用冲突
    used = 本轮已分配的目标 patch（icz 预留整个 pair）
    buffer_stages = []
    while D 存在环:
        Q = 一个环中所有移动对应的逻辑比特
        free = 当前空闲且不在 used 中的可路由 patch
        若 free 为空，报告没有可用缓冲 patch
        在所有 (q ∈ Q, p ∈ free) 中，选择二维距离最短的组合
        同距离按逻辑比特 ID、patch ID 选择
        将 q → p 记录为一个缓冲 AOD stage，加入 buffer_stages
        更新 q 的当前位置，将 p 加入 used
        以更新后的位置重新生成 moves 和依赖图 D
    groups = []
    assigned = 空字典，记录每条 Move 的 stage 编号

    while 还有未分组的 Move:
        ready = 所有前驱均已分配 stage 的未分组 Move
        move = ready 中 (二维移动距离, q.id) 最小的 Move
        first_stage = max(assigned[p] for p in D 的前驱(move))
        若 move 没有前驱，first_stage = 0

        从 first_stage 开始，按 stage 编号递增查找第一个组 C，使得:
            move 与 C 中每条移动均满足下方非交叉条件
        若找到，将 move 加入 C
        否则将 [move] 作为新组加入 groups
        assigned[move] = move 所在组的编号

    for C in groups:
        n_in[C] = entanglement → storage 的移动数量
        n_out[C] = storage → entanglement 的移动数量
        priority[C] = n_in[C] - n_out[C]

    建立 stage 依赖图 T：
        对 D 中每条边 B → A:
            若 assigned[B] != assigned[A]:
                在 T 中加入 assigned[B] → assigned[A]
        同 stage 的依赖不在 T 中添加自环

    对 T 进行拓扑排序：
        每次从当前无前驱的组中，选择 priority 最大的组
        priority 相同时按组创建序号选择
    按此顺序重放移动，检查起点、目标占用和 pair 预留
    若重放失败，报告发生冲突的组和 patch
    return buffer_stages + 排序后的 groups
```

这里“组与移动不冲突”指移动与组内每条移动均满足：

```text
sign(x_start_i - x_start_j) == sign(x_end_i - x_end_j)
sign(y_start_i - y_start_j) == sign(y_end_i - y_end_j)
```

沿用项目已确认的严格规则，x/y 的大小和相等关系都必须保持。论文 Fig. 5 也将不同坐标合并为相同坐标画为冲突；实现不要仅照抄正文中未完整覆盖相等情形的不等式。

移动依赖优先于距离排序：仅在前驱已分组的 Move 中选择距离最短者。stage 依赖优先于返回 storage 的排序：仅在前驱 stage 已输出的组中选择 priority 最大者，不能直接对全部 groups 按 priority 排序。

重放同一个 stage 时，允许某条 Move 的目标由本 stage 中另一条 Move 让出。校验通过后，统一释放所有起始 patch，再登记所有目标 patch，得到 stage 完成后的状态；不能按逐条更新造成临时占用冲突。目标由其他 stage 中的码块占用时，该码块必须已在之前的 stage 移走。

以上依赖与缓冲处理是本项目对 PowerMove 的补充。缓冲区从当前路由允许使用的 storage data patch 和 entanglement patch 中选择，不使用固定辅助区域。选择距离 Q 最近的 patch，定义为最小化任一 q ∈ Q 到该 patch 的二维距离；该 q 先移入缓冲区，之后再移往其最终目标。最终目标方案中预留的 pair 不用作缓冲区。

缓冲移动作为前置 AOD stage 输出，剩余移动继续使用上述 PowerMove 分组与依赖排序。每个缓冲 patch 在本轮中标记为已使用，不能再次选为缓冲区。所有额外缓冲 stage 计入总代价；它们不改变最终目标位置。非交叉、目标互斥和 icz 的 pair 独占要求仍须满足。

距离用于 PowerMove 的启发式选择和分组，stage 顺序使用论文的进出 storage 数量差；当前统计代价仍为 `cost_fn(stages) = len(stages)`。顺序调整本身不减少 stage 数，不宣称该方法保证最少 stage 或最短总执行时间。

来源：Ruan 等，*PowerMove: Optimizing Compilation for Neutral Atom Quantum Computers with Zoned Architecture*，用户提供的 arXiv:2411.12263v1，§4.1（PDF 第 5 页）、§5.2–5.3（第 6–7 页）、§6.1（第 7 页）。[原论文](<D:/paper/NAQC/PowerMove.pdf>)。

## 10. 实现与验证

先实现上述三个函数，再接入已有编译 DAG。代价通过普通函数参数传入；deformation 内部移动和二次调度只保留未来调用位置，当前不编写空接口类。独立校验可实现为一个重放函数。

必须检查：

1. 每条 DAG 指令恰好调度一次；允许同一 CZ block 内重排，block 外依赖保持，后续普通指令和 deformation 不得提前执行。
2. 普通门、deformation、CZ/icz 的优先级符合 9.2 节。
3. CZ 使用同一 pair 且 orientation 合法；icz 独占 pair。
4. 每条 Move 的起点正确、目标无冲突，每个 stage 满足非交叉约束；对 B → A 检查 stage(B) <= stage(A)，stage 重排序后仍成立。
5. 数据码块可以返回不同于初始位置的空闲 data patch，辅助码块不移动。
6. 重放后的最终位置与算法输出一致，stage 数与 L 中 AOD IB 数一致。

测试还应覆盖贪心着色的逻辑比特冲突与 pair 容量、二维最近空位、就绪移动中的距离升序选择、同 stage 内让出目标 patch、依赖导致的跨 stage 等待，以及返回 storage 优先级不得颠倒 stage 依赖。循环依赖应选择最近未使用空闲缓冲 patch；多个环不能重复预留同一缓冲 patch，无空闲缓冲区时返回明确诊断。

测试覆盖：无 CZ、单 CZ、单 icz、共享逻辑比特的连续 CZ、CZ 与 deformation 交替、容量不足、非交叉约束不满足、目标被占用，以及第 7 节的两个 block 划分样例。
